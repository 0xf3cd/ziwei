## 运行检查

安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，在仓库根目录运行：

```sh
uv sync --locked --python 3.14
uv run --locked python tools/check.py
```

支持 Python 3.11–3.14，原生依赖的平台要求见[安装要求](../README.md#安装要求)。
CI在Linux x86_64的3.11／3.14、Linux ARM64的3.14和macOS／Windows3.14上运行同一命令。
本地验证下限时使用 `uv sync --locked --python 3.11`。
优化模式也使用`tools/check.py`入口；它为pytest设置所需的警告过滤，裸跑`python -O -m pytest`不等价。

该命令检查 Ruff lint 与两空格格式、严格 mypy、普通与优化模式下的 pytest、文档本地链接、
严格 HTML／doctest 全量构建、sdist 内容及隔离安装的 wheel。
API 检查比对源码中的公开类、函数、方法及显式类型别名与实际 HTML 签名，拒绝被渲染成正文的指令。
知识参考页从内置记录与配置定义生成，检查字段、口径表配对及稳定锚点；遗漏成员或指向未知记录都须失败。
标准库类型链接使用随文档保存的离线 inventory，不在构建时下载。
锁定开发组同时提供build和setuptools后端，`python -m build --no-isolation`经sdist构建wheel。
sdist须带全源码、测试、工具、workflow、文档、锁文件与协作约定，
不得夹带 `.review/`；构建前删除 `src/*.egg-info`，旧的文件清单会掩盖 `MANIFEST.in` 的变化。
安装后在仓外以隔离模式导入包，分别运行普通与优化模式的检查。运行时依赖按锁文件hash安装，
本项目wheel用`--no-deps`安装；消费前后比对产物hash，拒绝被改写的文件。
临时 HTML、doctest 报告、分发包和安装验证环境优先使用 `SCRATCH`，否则使用系统临时目录，
退出时删除。构建元数据和工具缓存可能保留在仓内已忽略的目录中。
显式传入`--artifacts-dir`可将同一份已核产物保留到空目录，详见[发布准备](releasing.md)。

工具版本由 `uv.lock` 锁定：Python 3.11 使用 Sphinx 8.2.3，较新 Python 使用 Sphinx 9.1.0。
覆盖率报告用于定位遗漏。当前测试覆盖历法解析、安星、四化与大限、整盘组合、文本显示和知识查询，
并包含独立参考盘例及合成取证。各项证据的适用范围见[完整命盘](chart.md#参考盘例与验收限度)，不把组件联动当成独立整盘认证。

CI的uv版本与各平台下载归档摘要在工作流中固定；摘要取自uv发布资产并与实际归档字节核对。
第三方action均使用完整提交SHA，浮动tag由回归测试拒绝。

本地格式化运行 `uv run ruff format .`。任一命令失败即停止，修复原因后重跑。
依赖变更须更新锁文件并通过两个 Python 端点；忽略规则或警告时应限制范围并说明原因。

若要保留 HTML 供检查，可构建到已忽略的 `build/` 目录：

```sh
uv run --locked python -m sphinx -E -a -n -W -b html -c docs . build/docs
```

打开 `build/docs/docs/index.html`。

按上面的`uv sync`从本仓安装开发源码，本地分发名／版本为`ziwei`／`0.1.0`。
首次发布前须再核 PyPI 名称可用性。可检查已安装的开发版本：

```{doctest}
>>> from importlib.metadata import version
>>> version("ziwei")
'0.1.0'
```

## 设计

输入、配置、规则和结果默认采用不可变值。冻结 dataclass 仍不能冻结内部的列表或字典；
使用不可变成员，或在边界复制并隔离可变输入。调用方在构造后改动原始输入，不应改变已存命盘。

优先使用参数和返回值明确的普通函数。文件读取、原生库初始化与缓存由所属边界显式负责。
导入包或查知识不应触发排盘。

表格形规则用数据表达，计算用函数表达。定义归领域模块，入口负责组合。
有真实调用方共用一个合同再提取抽象，潜在的未来后端不算调用方。
含义尽量进入名字与类型，再由注释补充理由。

配置必须影响它所描述的计算。拒绝不支持的选择，保留请求和实际生效口径。
避免隐式全局设置、静默替代，以及返回类型依赖隐藏状态的工厂。

## 正确性

除代表值外，还要测试领域边界：闰月、早晚子时、正月初一与立春之间、立春瞬间两侧的时标比较、
支持范围端点、真太阳时跨日、缺失信息与不支持的组合。公开输入校验在 `python -O` 下也必须有效。

参考盘例记录来源、口径配置、农历算法与版本、时区与真太阳时处理。往返测试检验保真，
重新计算检验执行，独立来源检验一致性。外部排盘器是下游参考，不是一手来源；
说明参考盘例为什么能发现要测的缺陷。

示例使用合成数据或适当匿名化的盘例。历法数值的验证与命盘解读的主张分别处理。

## 知识与文档

遵循[知识设计](knowledge.md)，解释文字链接稳定的概念、规则与来源标识。
引文保留原文；来源已核实，不能证明某张盘满足条目前提。

行为变化时同步更新文档。公开 docstring 以中文说明合同；标识、签名、单位、默认值只有一份来源。
运行例子并检查生成页面。

## 审阅依据

使用 AI 编写的贡献仍由贡献者负责。在 PR 中说明对应 issue、行为变化、实际运行的检查和未解决问题，
区分已经执行的验证与建议以后运行的检查。

审阅检查来源是否忠实、假设是否成立、可变成员是否隔离、失败行为、抽象是否多余及口径记录是否完整。
lint 通过或覆盖率很高不能回答这些问题。修改检查程序时，同时提供应通过的输入与应拒绝的缺陷。

合并和发布需要维护者批准。CI 负责报告检查结果；若要自动阻止未通过检查的合并，
还需在仓库规则中将它们设为必需检查。
