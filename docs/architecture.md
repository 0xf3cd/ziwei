# 仓库结构与计算边界

[项目入口](../README.md) · [知识组织](knowledge.md) · [参与开发](contributing.md)

本文是初始设计，不表示 API 已实现。首个目标是可复现的本命盘：安星、生年四化与大限，
并能独立查阅排盘所依据的规则与出处。

## 结构组织

建议采用下面的包布局。首次功能出现时才建立对应模块；目录图里的名字不要求预建空包或额外层次。

```text
src/ziwei/
  birth.py          原始出生记录与解析后的计算输入
  config.py         闰月、子时、换年口径与流派选择
  calendar.py       celestial-calendar 的具体适配
  ganzhi.py         天干、地支、六十甲子、纳音与五虎遁
  palaces.py        命宫、身宫、十二宫与宫干
  bureau.py         五行局
  stars.py          主星与辅星的安星表
  sihua.py          生年四化的具名变体
  decades.py        大限的顺逆与起止
  chart.py          组合与不可变命盘结果
  serialization.py  带版本的记录与恢复
  knowledge/        概念、来源、条目及独立查询
tests/              领域测试与真实安装消费测试
docs/               中文指南与说明
```

可执行定义归各自领域模块。`chart.py` 负责组合及完整命盘的成功条件，不收容所有共享定义。
有真实共同使用方时才提取共享值模块。包导入与知识查询不得初始化 celestial。

## 出生资料与时间

保留原始日期、历法、钟点、精度、性别、地点、来源与时区信息；另存解析后的计算输入及消歧选择。
输入可以是公历民用时刻加 IANA 时区或显式 offset，也可以是农历年月日时加闰月标志。
附加一个时区对象不会自动检查夏令时空缺或选择重叠时刻，解析层须显式处理。

解析后的计算输入是：农历年、月、日、时辰、闰月标志、性别阴阳，以及按所选换年口径得到的年干支。
真太阳时是可选步骤：给出经度时，先用 celestial 的均时差换算当地真太阳钟，再取时辰；
不给经度时按民用钟取时辰，两种路径都记入结果。

换年口径为立春时，出生时刻与立春时刻必须在同一时标下比较。celestial 的节气时刻是 UT1，民用输入是 UTC 或固定偏移；
解析层先把两者归到同一时标，记录所用转换与精度，不直接比较钟面数值。转换资料不可用时显式失败，
或采用写明的近似并记入结果。测试覆盖立春瞬间两侧。

完整命盘入口要求已知时辰与性别。未知时辰可以表达，但该入口须拒绝，不能代填子时。
1972 年前的历史时刻另定时标合同，不把现代 UTC 规则向前外推。

## 三个口径

| 口径 | 具名选项 | 影响 |
|---|---|---|
| 闰月归属 | 全月归下月；全月归本月；上半月归本月、下半月归下月 | 命宫、身宫、左辅右弼等按月安星 |
| 子时换日 | 晚子时归次日；早晚子时同日 | 农历日，进而影响紫微星位置与整盘 |
| 换年 | 农历正月初一；立春 | 年干支，进而影响生年四化、禄存、天魁天钺、火铃、天马 |

三个口径互相独立，各自进入命盘记录。默认值先解析成具名选择再进入记录；配置不影响它所描述的
计算时视为缺陷。各选项的来源与适用条件写在实现旁，见[知识组织](knowledge.md)。

## 历法与安星

celestial-calendar 负责公历与农历互转、闰月与各月长、节气时刻、均时差与真太阳时；它有三套
农历算法，各有日期基准与支持范围，所选算法随结果保存。它没有干支 API，六十甲子、纳音与五虎遁
是本仓自持的小型声明式表，带出处。

本仓据解析后的输入完成安星：

1. 命宫与身宫由生月与生时定；宫干由年干经五虎遁推出。
2. 五行局由命宫干支的纳音五行定。
3. 紫微由五行局与生日定；紫微系与天府系其余主星按与紫微、天府的固定关系安入。
4. 六吉、六煞、禄存与天马分别按年干、年支、生月或生时安入。
5. 生年四化按年干查具名变体的四化表。
6. 大限起于命宫，起始年龄为五行局数，阳男阴女顺行、阴男阳女逆行。

下列选择分别表达：

| 选择 | 示例 | 改变的是什么 |
|---|---|---|
| 同一量的算法 | 农历算法 ALGO1／ALGO2／ALGO3 | 计算方法与支持范围 |
| 定义或流派规则 | 庚干、壬干四化的不同口径；天马按年支或月支 | 所求问题的定义 |
| 实现手段 | 查表、缓存、等价数值实现 | 内部执行；除非公开结果也改变 |

星曜身份不随流派选择消失。同名星曜在不同流派中安法不同时，是同一概念的不同规则变体，
不是两颗星；查法不同（按年支还是按月支）时同样作变体表达。

## 组合与失败

计算输入、宫位框架、星曜落宫、四化与大限分别表示。完整本命盘可以要求全部请求组件成功；
将来的部分命盘入口须明确自己的成功条件。

请求的口径或流派变体没有定义时须明确报告。将来若允许替代，必须显式选择策略，并记录请求与
实际生效的口径。农历日期超出所选算法范围、闰月与日的组合不存在，同样显式失败。

## 可复现性

保存原始输入、已解析口径与流派、农历算法与版本、解析后的计算输入及派生结果。
恢复已存结果是保全记录，重新计算是再次求值，两者的兼容要求不同。首个序列化设计须包含
schema 版本，以及所需算法版本不可用时的行为，不能含糊地“反序列化并重算”。

与 celestial 一致检验历法适配；同口径独立盘例检验完整结果。测试覆盖闰月、子时、正月初一与立春
之间的出生、立春瞬间两侧、支持范围端点、真太阳时跨日、各流派四化变体与大限顺逆。

## 交付顺序

先建立出生／口径值与小型独立知识目录，再完成命宫、五行局与主星，加辅星、四化与大限，
最后完成序列化、文本盘面、文档与安装包验收。

任务状态归 [v0.1.0 milestone](https://github.com/0xf3cd/ziwei/milestone/1)。
包结构随实际实现中出现的共用关系调整，不以通用后端或插件框架为前置。
