# 知识组织与来源

[项目入口](../README.md) · [结构设计](architecture.md) · [参与开发](contributing.md)

本仓同时服务排盘与知识学习。查询知识不应要求先有命盘、出生资料或已加载的 celestial 原生库。

## 记录与归属

概念、规则变体、来源与知识条目使用稳定、与语言无关的标识。这些是记录职责，
不要求每种职责都独占一个类或文件；首个 schema 要用少量真实语料检验。

| 记录 | 保存什么 |
|---|---|
| 概念 | 身份、种类（星曜、宫位、四化、五行局、口径、流派）、名称与别名、相关概念 |
| 规则变体 | 定义、所属流派、适用范围与条件；可执行时链接实现中的表或函数 |
| 来源 | 书名或作者、版本或刊本、定位、文本层（白文、注释、今人说明）、来源谱系、支持的论断与限度 |
| 知识条目 | 陈述、关联概念／规则／来源、前提、例外、限度及整理状态 |

可执行常量与规则表归领域实现。知识条目链接规则标识，生成的参考表读取可执行定义。
解释文字说明原因与范围，不再维护第二份安星表。

原文引述、今人说明、仓内原作说明是不同文本层。同一祖本的多份转抄不构成独立来源；
措辞逐字相同的两处只算一路。保留原文措辞与定位，记录收录材料的转载权限。

## 来源与规则的三层问题

一条安星规则绑着三个可以分开回答的问题，一份来源常常只定其中一个：

1. **系统归属**：这条规则属于紫微斗数，还是同名星曜在其他术数中的规则。
2. **规则**：表、偏移、组合条件。
3. **查法**：锚在年干、年支、生月还是生时；安在十二宫的哪一类位置。

记录每份来源定了哪一层、没定哪一层。起算约定（含不含起点）原文未载时，只有例解能裁；
找不到例解就并列保留两读。同名异物、转抄冒充独立来源、底本差异是常见失败形状，
各自要有翻案条件：一个具体的检索动作，而不是“以后再研究”。

## 状态需要分开表达

沿用 [bazi](https://github.com/0xf3cd/bazi) 知识层的区分，具体枚举值与默认展示规则按本领域设计：

1. 所列出处核实了吗？
2. 条目的前提已理解并表达清楚了吗？
3. 条目可以进入默认输出吗？
4. 某张具体命盘满足已经表达的前提吗？

出处核实不能单独证明适用；检索到相关陈述，也不能证明它适用于当前盘。
将来的判别器须区分满足、不满足、未知。只验证部分条件时，只能返回部分证据。

## 首个可用范围

先整理本命盘实际使用的概念：十四主星、六吉六煞、禄存天马、十二宫、五行局、生年四化、
三个口径与大限规则。为这些安星规则补足可核验来源，并把流派差异记为具名变体；
已知的分歧点包括庚干与壬干的四化、天马按年支或月支、闰月与子时的归属。

首批语料只收安星规则的查法与出处，不收吉凶解释；解释知识与前提判别属后续 milestone。
缺乏依据的规则不进入默认表，作待决记录并配翻案条件。

首个目录支持列概念与变体、按名称与别名查找、过滤条目与来源、独立查看引用。
交付一组有原文、规则引用及有条件／前提待定条目的完整例子，验证这些条目不会自动变成
当前命盘适用的结论。

## 文档检查

API 和知识目录参考页从各自定义生成。手写指南按读者任务组织：排一张盘、比较口径、
查知识、看出处、增加有来源的变体。

文档检查核本地链接、稳定条目链接、未知引用、重复标识与可执行例子。除了构建成功，
还要核实际 HTML：成员或说明漏掉，构建仍可能全绿。

发布文档标明代码与语料版本，区分开发页与已发布页。部署另行执行；当前 Markdown 文档就是可读入口。
